# Go Product Platform v16: последовательная разработка с агентами

## Цель

Соло-разработчик или команда из 3–5 человек поручает агенту вертикальную E2E-фичу.
Агент сначала фиксирует требования и дизайн, затем план, реализует срезы,
собирает доказательства и передаёт кандидата независимому рецензенту.
Платформа блокирует пропуск этапов и устаревшие доказательства на уровне CLI.

## Область и допущения

- Git остаётся источником истины; по умолчанию задачи также в Markdown.
- Используем существующие глобальные навыки без форка и без скрытой установки.
- Документы продукта хранятся в Git; `.go-product-platform/` — восстановимый кэш.
- Низкий/средний риск в уже согласованном объёме проходит этапы автоматически.
  Высокий риск и выпуск требуют ссылки на явное решение человека.
- Все новые артефакты — Markdown с ограниченным, проверяемым YAML frontmatter.
- CLI использует Python 3.10+ и стандартную библиотеку; полный YAML не требуется.
- Машинная проверка структуры и воспроизводимости не доказывает правдивость текста
  и независимость личности рецензента. Защищённая ветка/CI — внешняя граница контроля.

## Критерии приёмки

- AC-01: `gpp init --offline` создаёт минимальную отслеживаемую основу документации,
  не переписывает пользовательские документы и не обращается к сети/глобальным навыкам.
- AC-02: новая фича получает уникальный ID, требования, дизайн, план, задачи,
  проверку и ревью; переходы выполняются только по порядку.
- AC-03: незаполненные обязательные разделы, неизвестные ссылки на ID, дубли,
  циклы зависимостей и незавершённые задачи блокируют соответствующий переход.
- AC-04: изменение утверждённых входов требует нового цикла согласования;
  изменение кода делает результаты тестов и ревью устаревшими.
- AC-05: CLI сам запускает явно указанную команду проверки и записывает результат,
  код возврата, Git-кандидата, хеш входов и журнал; для E2E-фичи нужны unit и e2e.
- AC-06: готовность требует независимого ревью, отсутствия блокеров,
  обновлённой затронутой документации и проверки текущего кандидата.
- AC-07: HLD/LLD/ADR/API/Data/Event/Debt/Initiative имеют общий контракт метаданных;
  необязательные документы создаются по влиянию изменения, а не массово.
- AC-08: миграция v15 сохраняет выбор навыков и существующие файлы; установленная
  и восстановительная копии CLI умеют выполнять SDD-команды.
- AC-09: handbook v16 описывает команды, ограничения, соло/командный процесс,
  владение worktree, вертикальные срезы, риск, выпуск и сопровождение документов.

## Проверки

`python3 -m unittest discover -s tests -v`; негативные сценарии этапов,
устаревших доказательств, миграций и сохранности пользовательских файлов.
`uv run --with beautifulsoup4 python build.py` собирает автономный handbook.

## Вне объёма

Новый внешний репозиторий навыков, интеграция с платным трекером, автоматический
production deploy, настройка сервера Git и криптографическая аттестация агента.
