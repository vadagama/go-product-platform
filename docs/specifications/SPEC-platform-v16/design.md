# Дизайн GPP v16

## Решение

`installer/sdd.py` — автономный модуль стандартной библиотеки Python, подключённый
к существующему parser gpp. При install-cli поставляется с репозиторием; при init
копируется рядом с восстановительным gpp.py. Существующая модель глобальных
навыков не меняется. Профили расширены инженерными навыками из курируемого каталога.

Документы продукта создаются только при отсутствии, хранятся в Git. Bootstrap
копирует стандарт в игнорируемые материалы и добавляет точку входа в AGENTS.
Ни новый набор навыков, ни сетевые зависимости не устанавливаются скрыто.

## Контракты и данные

Плоский YAML 1.2 с JSON-совместимыми значениями позволяет обойтись без внешнего
парсера и отклонять неподдерживаемый синтаксис. Общие поля и обязательные разделы
определяет модуль; шаблоны выдаёт CLI, поэтому нет второй копии схемы.

state задаёт текущий этап/цикл; gates фиксируют входы, evidence — исполненные команды.
Хеш исходников включает неигнорируемые новые файлы, режим исполнения и подмодули.
Служебные отчёты исключены; содержание задач фиксировано, checkbox изменяем.
Финальные evidence требуют чистого кандидата; последующий коммит отчётов допустим.

## Риски и альтернативы

Полный YAML/Pydantic добавил бы зависимость к bootstrap. Выбран документированный
поднабор; сторонние документы требуют явного приведения к стандарту.
Локальные файлы не являются системой авторизации и могут быть намеренно подделаны.
Полноту тестов и реальность независимого ревью подтверждает человек/отдельный агент,
запрет обхода merge — защищённая ветка с required CI и доверенными тестами продукта.
Один пишущий агент на фичу — обязательная предпосылка, распределённой блокировки нет.
