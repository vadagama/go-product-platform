## 49. ADE v15: интерактивная установка и управление навыками ИИ через агента {#ade-skills-manager-v15}

**Нормативное решение v15 (заменяет порядок ручной установки из исторических глав 47–48):** пользователь описывает задачу Codex, Claude Code, Zed или Orca, а агент самостоятельно выполняет диагностику и настройку через установленный `gpp`. Установка и обновление навыков **всегда требуют явного подтверждения**. Есть также терминальный мастер вопросов `gpp wizard` для первого запуска без агента.

### 49.1. Архитектура: один глобальный каталог, выбор по проектам {#ade-v15-architecture}

Наличие навыка в глобальном каталоге не означает его обязательное применение. Каждый продукт фиксирует список активных глобальных навыков в **отслеживаемом** `go-product-platform.lock.json`. Инструкции одного продукта не распространяются на другой. Реализации проектных уникальных навыков остаются под `.go-product-platform/project-skills/` и не публикуются глобально автоматически.

| Где располагается | Содержимое | Версионирование |
|---|---|---|
| `~/.agents/skills/` | Общие навыки для Codex/Zed и совместимых сред | Глобальный SHA lock |
| `~/.claude/skills/` | Общие навыки для Claude | Тот же SHA lock |
| `~/.agents/go-product-platform/` | Git снимки, история обновлений, global-skills.lock.json | SHA каждого источника |
| `my-product/go-product-platform.lock.json` | Версия платформы, профиль, список активных имен | Отслеживается Git |
| `my-product/.go-product-platform/` | Руководство, конфигурация, активные навыки, локальный управляющий навык | Игнорируется Git |
| `my-product/AGENTS.md`, `CLAUDE.md` | Малый bridge к глобальных навыков и локальному manager навык | Отслеживается Git |

### 49.2. Сценарий первого запуска: мастер вопросов {#ade-v15-wizard}

**Опросник начинается с объяснения, что доступно**, а не с установки всего каталога. Последовательность:

1. Показать категории: Серверная часть на Go, PostgreSQL, Protobuf/Buf, Wails, React/shadcn, тесты, iOS/Android, AI SDK, Graphify и Orca.
2. Спросить разрешение прочитать только списки `SKILL.md` в двух глобальных каталогах. Если пользователь отказался, проверку пропустить.
3. Предложить профиль `go-api`, `web`, `desktop`, `mobile-native`, `ai` или `custom` и вывести имена и краткие описания входящих навыков.
4. Предложить включить дополнительные глобальные навыки в выбранный проект. **Активация не копирует файлы в проект.**
5. При согласии проверить отсутствующие навыки, показать источники GitHub; **отдельно запросить разрешение** на глобальную установку конкретных навыков.
6. Отдельно предложить **только проверку** обновлений на GitHub (сетевой запрос). При наличии версий показать текущий и предлагаемый commit SHA.
7. Вывести итоговый план и запросить финальное согласие. Отказ отменяет изменения и в проекте, и в глобальных каталогах.

Пример разговора с агентом:

> **Пользователь:** Настрой этот проект под Go API и React. Посмотри, какие навыки уже установлены, и предложи необходимые. Ничего пока не устанавливай.
>
> **Агент:** Можно использовать Тестирование Go, Go architecture, Buf/Protobuf, shadcn и Playwright. Разрешить проверить наличие в `~/.agents/skills` и `~/.claude/skills`?
>
> **Пользователь:** Да.
>
> **Агент:** Пять навыков есть, двух не хватает. Предлагаю активировать семь для проекта, а два отсутствующих установить глобально из указанных GitHub-репозиториев. Подтверждаешь?

Терминальный эквивалент — `gpp wizard --project .`, но **пользователь не обязан вводить его вручную**: агент использует машинный JSON-инвентарь и задаёт вопросы в чате. Терминальный мастер предназначен для пользователей, открывающих локальный starter kit без работающего агента.

### 49.3. Проектный skill-manager: агент обслуживает платформу {#ade-v15-manager-skill}

В каждом проекте при `gpp init` появляется:

```text
my-product/
├── AGENTS.md
├── CLAUDE.md
├── orca.yaml
├── go-product-platform.lock.json
└── .go-product-platform/
    ├── active-global-skills.md
    ├── handbook/
    ├── project-skills/
    │   └── go-project-platform-manager/
    │       └── SKILL.md
    ├── graphify/out/
    └── tools/gpp.py
```

**Это единственный автоматически создаваемый проектный управляющий навык.** Он существует потому, что знает конкретный профиль и правила данного проекта. Общие навыки по Go, Wails, React, Protobuf, Graphify и Orca остаются глобальными. Управляющий навык вызывается через инструкции `AGENTS.md`/`CLAUDE.md`, а не за счёт дублирования в `.agents/skills` проекта.

Возможности для запросов на естественном языке:

| Запрос пользователя | Что делает агент | Граница безопасности |
|---|---|---|
| «Какие навыки у меня есть?» | С согласия читает глобальный инвентарь и активный список проекта | Не устанавливает ничего |
| «Включи Wails и UI-навыки» | Предлагает изменение профиля и записывает выбранные имена в project lock | Только после подтверждения |
| «Установи недостающие» | Выводит точные GitHub-источники, ставит выбранные навыки глобально | Отдельное согласие на установку |
| «Проверь обновления» | Получает upstream SHA для уже используемых источников | Только чтение, нет обновления |
| «Обнови эти навыки» | Проверяет источник, историю и согласованный exact-SHA план | Отдельное согласие; влияет на все проекты |
| «Проверим окружение» | Проверяет документацию, project bridge и наличие **активных** навыков | Без изменения глобальных каталогов |

### 49.4. Контракт управления и CLI для агентов {#ade-v15-cli}

В отличие от большого скрипта с побочными эффектами, управление разбито на команды с разными разрешениями. Команды **исполняет агент**; они приведены в аккордионах как архитектурный интерфейс.

```sh
# Прочитать наличие глобальных skills после согласия пользователя.
gpp skills-inventory --project . --json

# Зафиксировать профиль продукта после согласия пользователя.
gpp skills-activate --project . --profile web --approve

# Установить именно указанные curated skills глобально после согласия.
gpp skills-install-global --names golang-testing,protobuf,shadcn --approve

# Для Graphify и Orca использовать официальные установщики (подтверждение отдельно).
gpp skills-install-external --names graphify,orca-cli --approve
```

Для проверки и актуализации навыков:

```sh
# Проверка свежести — только чтение GitHub, без установки.
gpp skills-check-updates --project . --selected-only --json \
  --output .go-product-platform/update-plan.json

# После анализа списка коммитов и ОТДЕЛЬНОГО согласия пользователя.
gpp skills-upgrade-global \
  --plan .go-product-platform/update-plan.json --approve

# Управляемые отдельно Orca/Graphify skills.
gpp skills-update-external --names orca-cli,graphify --approve
```

Файл плана содержит исходный SHA, предложенный SHA и репозиторий. Обновлятор проверяет, что HEAD **не изменился с момента согласования**, и не переписывает чужой глобальный skill-директорий. Старые снимки сохраняются. Если актуализация вызывает конфликт с пользовательским навыком, она останавливается без принудительной замены.

**Особенность обновления каталога:** проверка отслеживает уже закреплённые Git-источники. Новые имена навыков, которых ещё нет в манифесте Go Product Platform, включаются через отдельное версионированное обновление каталога платформы; они не устанавливаются автоматически только из-за того, что появились на GitHub.

### 49.5. Глобальные изменения и совместимость между проектами {#ade-v15-global-updates}

Обновление навык влияет на **все** проекты на машине, потому что все они используют одну глобальную копию. Поэтому управляющий agent обязан показать:

- какие навыки и проекты потенциально затронуты;
- ссылки на источники и старый/новый commit SHA;
- меняется ли команда установки/запуск скриптов;
- план проверки после обновления и путь восстановления прежнего snapshot;
- какие навыки обслуживаются независимо (Orca/Graphify) и не покрываются обновлением снимков курируемых Git-репозиториев.

Чтобы проверка обновлений не влияла на кратчайший девелоперский цикл, ее запускают **только по просьбе пользователя** (либо после отдельно согласованной политики), а не в `orca.yaml` и не при каждом создании worktree. <a href="https://orca.dev/docs/cli/skills">Orca</a> умеет управлять собственными глобальными навыками через встроенный updater; команду `orca skills update` следует запускать с явным согласованием. Для Graphify используется официальный `uv tool upgrade graphifyy`.

### 49.6. Воспроизводимость и миграция с v14 {#ade-v15-migration}

Уже установленная v14 не обновляется скрыто: новый доверенный стартовый набор сначала заменяет CLI, затем агент предлагает **явную** миграцию проекта и согласование его активного профиля. Все `AGENTS.md`, существующие уникальные проектные навыки, индивидуальные hooks Orca и пользовательские глобальные навыки сохраняются.

```sh
# Этот набор выполняет агент после подтверждения пользователя.
python3 installer/gpp.py install-cli
gpp migrate --project .
gpp skills-inventory --project . --json
gpp doctor --project . --strict
```

В дальнейшем **каждый Orca worktree** выполняет исключительно `gpp init --project . --offline`; это восстанавливает локальную документацию, управляющий навык и описание активных навыков без сети, глобальных изменений, Docker build или тяжелых проверок.

### 49.7. Критерии приёмки {#ade-v15-acceptance}

| Инвариант | Проверка |
|---|---|
| Пользователь отменил опросник | Никаких изменений в проекте или глобальных навыков |
| Пользователь отказал в чтении global каталогов | Нет проверки каталогов в опроснике |
| Навык активирован для проекта | Изменился только project lock и локальная сводка, глобальные навыки не копируются |
| Глобальный навык отсутствует | Отображается статус, установка только с отдельным подтверждением |
| User запросил «проверь обновления» | Только JSON-план и SHA, обновления не применяются |
| Upstream изменился после проверки | Отказ обновления, требуется новый план |
| Конфликт с чужим глобальным навык | Никакой принудительной перезаписи |
| Появился новый worktree | `gpp init --offline`, без сети и обновления навыков |
| Уже есть собственный проектный навык | Он сохраняется при повторной установке и миграции |

**Результат:** после первоначального доверенного подключения платформы пользователь управляет навыками в ADE обычными сообщениями, а не терминальными командами. Агент обязан объяснять последствия, получать подтверждение и проводить фактические операции с проверяемыми результатами.
