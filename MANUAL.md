# Обслуживание репозитория платформы

Это инструкции для самого go-product-platform. Настройка целевых продуктов
описана отдельно в platform/references/graphify-installation.md.

## Graphify

Используется установленный graphifyy 0.9.111 (проверено 2026-11-25). Новая установка:

```sh
uv tool install graphifyy==0.9.111
graphify --help
graphify hook install
graphify hook status
```

Существующий CLI не обновлять автоматически. Проектный навык хранится в
`.agents/skills/graphify/` и `.claude/skills/graphify/`; SOURCE.json содержит
контрольные суммы локального снимка и upstream URL. SHA upstream этого снимка
не установлен; версия CLI не выдаётся за ревизию навыка. Повторную установку
из upstream выполнять с проверкой diff, не перезаписывать местные правила.

Область анализа: корневые README, CHANGELOG, AGENTS, CLAUDE, MANUAL и весь
platform/ (включая **исходники** распространяемых навыков). Исключения —
.graphifyignore: установленные копии навыков, .git, .codex, кеш и результаты сборок.
После изменения исключений проверить detect и выполнить семантическое обновление.

## Построение и запросы

В ADE вызвать проектный навык `$graphify` с аргументами `. --directed` (slash-форма для
поддерживающих сред — `/graphify . --directed`). Это вызов навыка, не команда shell.
Он выполняет семантический анализ документов средствами агента, кеширование,
построение, кластеризацию и экспорт. Направленный граф сохраняет встречные
ссылки между документами как разные связи. API-ключ для этого способа не требуется.
Headless extract требует настроенного LLM backend; code-only не заменяет анализ
этого репозитория. Генерируемые файлы — graphify-out/graph.json, GRAPH_REPORT.md,
graph.html, manifest.json и кеш; все игнорируются Git.

```sh
graphify query "go-product-modernization" --budget 2000
graphify query "engineering.yaml UI prototypes ADE" --budget 2000
graphify explain "go-product-modernization"
graphify export html
graphify check-update .
```

check-update проверяет pending, а не весь состав файлов. Сопоставлять исходники
с manifest и проверять новые/удалённые файлы. После правок документов вызывать
`$graphify` с `. --update --directed`. Не снимать pending до фактического обновления.
Для локальной слежки — `graphify watch .`; остановка Ctrl+C. Постоянный фоновый
процесс при настройке не запускается. Watcher/хуки не выполняют LLM-анализ документов.

## Хуки и worktree

В основном checkout установлены post-commit, post-checkout, post-merge и
post-rewrite через официальный `graphify hook install`. Они локальны и не
переносятся Git; повторить установку в новом клоне. Перед повторной установкой
осмотреть эффективный core.hooksPath и сохранить пользовательские обработчики.
.gitattributes и локальный merge driver создаёт официальный установщик, хотя
в этом проекте graph.json не отслеживается. Не добавлять граф в Git ради driver.

`graphify codex install` использован для начального подключения; AGENTS.md затем
адаптирован к документному репозиторию. Он также создал .codex/hooks.json;
команда сделана переносимой через PATH. В 0.9.111 Codex PreToolUse hook-check —
намеренный no-op: правила анализа берутся из AGENTS.md, не из этого хука.
Не выдавать его за автоматическую актуализацию документов.

В 0.9.111 Git-хуки пропускают linked worktree (проверка common-dir в обработчике).
В worktree строить собственный граф и обновлять его через навык; не рассчитывать
на общий hook. Не копировать абсолютные .graphify_root/.graphify_python из другого
дерева. При повреждении сохранить прежний graphify-out вне области анализа,
повторить полный цикл навыка и проверить query и покрытие документов.

## Проверки изменений платформы

- `git diff --check` — формат патча.
- Проверка YAML/frontmatter и относительных ссылок затронутых документов.
- Проверка переносимости ссылок изменённых распространяемых навыков.
- Обновление семантического графа и запрос по изменённому контракту.

Фактические результаты настройки Graphify сохраняются локально в
`graphify-out/setup-verification.json`. Это evidence конкретного checkout,
не обещание готовности любого клона или продукта.

## Результаты проверки механизма (2026-11-25)

В изолированном временном Git-репозитории проверены: post-commit обновляет AST
после добавления функции/вызова; watcher обновляет код до commit и создаёт
needs_update после изменения Markdown. Коммит только Markdown в 0.9.111
**не создал pending**, даже при отключённом code-only: поэтому отсутствие
pending после commit не доказывает актуальность документации. Проверять manifest
и выполнять семантическое обновление через навык. Повторный hook install в этом
checkout не изменил обработчики. Checkout/merge/rewrite установлены, но их
функциональная проверка в этой сессии не выполнялась. Canvas здесь не установлен.
