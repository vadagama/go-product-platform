# LOCAL-NATIVE v11 — практическая локальная агентная разработка

**Этот файл — краткий старт.** Полный регламент: handbook.md, разделы 38–40.

- Зафиксировать Go 1.27.4 / Node 24 через `mise.toml`.
- Один PostgreSQL 18.7 нативно на macOS; PG19.0 после проверка концепции совместимости.
- Каждый Git worktree получает отдельные БД, пользователя, порты, логи, тестовые данные, результаты.
- Vite HMR и сервер Go живут как native процессы; не строить образ Docker при правке.
- `make check`/affected tests после изменения, E2E watcher в отдельном процессе.
- `scripts/e2e-watch.sh` — пример watchexec + Playwright; тестовый сервер из `web/playwright.config.ts`.
- Один финальный `make verify` на зафиксированном кандидате через локальный GitLab runner в соло.
- Если возникла потребность в командном CI — общий Linux runner; проверка нативного приложения macOS отдельно.
- Рабочая фича не равна релизу: упаковка и подписание после стабилизации.

Команды `devctl` — **интерфейс предлагаемого внутреннего инструмента**, его нужно реализовать.
Для рабочей среды манифест Compose и процедуры резервного копирования и восстановления заводятся при выходе на эксплуатацию.

# Профиль LOCAL-NATIVE — Mac + нативный PostgreSQL + рабочие деревья Git

Цель: итеративная локальная разработка без Docker и виртуальных машин. Go API, Vite и Wails запускаются как локальные процессы ОС. PostgreSQL 18 работает как одна служба macOS; каждое рабочее дерево получает собственную БД, учётные данные, порты и журналы.

## Инструменты разработки

- Go >= 1.26 для настольных приложений Wails v3 (зафиксируйте точную патч-версию через mise).
- PostgreSQL 18.7 и инструменты командной строки Postgres установлены локально.
- Buf + pnpm + Node + Git. Полный Xcode нужен только для сборок iOS; Android SDK/NDK — для Android.
- `mise.toml` демонстрирует локальные задачи; зафиксируйте точные версии инструментов в своём проекте.

## Жизненный цикл рабочего дерева

`devctl create my-feature` → `git worktree add` → выделение идентификатора рабочего пространства и резервирование портов → `CREATE ROLE`/`CREATE DATABASE` → миграции и тестовые данные → запуск процессов наблюдения → тестирование затронутых компонентов → интеграция → безопасная очистка.

Не передавайте непроверенные имена веток в SQL, команды оболочки или идентификаторы БД. Используйте реестр и атомарное резервирование портов. Удаляйте только БД, принадлежащие devctl; защитная проверка должна запрещать удаление `postgres` и объектов из пространства имён рабочей среды.

## Версия PostgreSQL

По состоянию на 18 ноября 2026 года последняя стабильная версия — **18.7**; **19 RC2** не является стабильной версией для эксплуатации; выход PostgreSQL 19 GA запланирован на 19 ноября. PG17.12 остаётся поддерживаемой версией и разумной базой для существующего проекта. Локально и на рабочей VM используйте одну основную версию.

## Проверка изоляции

Запустите рабочие деревья A и B одновременно. Проверьте, что пользователь БД A не может подключиться к B, порты различаются, миграции идентичны, хранилища объектов и тестовые данные раздельны. Остановите A и убедитесь, что B продолжает работать. Очистите A и убедитесь, что данные B сохранились.

## Локальная аутентификация и секреты

Используйте OIDC-провайдер только для разработки или одноразовые тестовые токены. Никогда не копируйте корневые учётные данные рабочего OpenBao или административный токен Rauthy в рабочие деревья.
