# Заказы — инструкции для агентов (Claude Code)

Эти инструкции применяются к Claude Code и совместимым агентам Anthropic,
работающим в этом репозитории. Содержимое зеркалирует `AGENTS.md`; отличаются
только вводный абзац и каталог навыков — проектные копии читаются из
`.claude/skills/`. При изменении правил синхронизируйте оба файла. Пути ниже
указаны от корня репозитория.

## Правила на каждый запрос

Перед ответом, планированием, исследованием, правками или запуском команд:

1. Если `using-agent-skills` включён в реестр, откройте и прочитайте
   `.claude/skills/using-agent-skills/SKILL.md`. Если не выбран, переходите к шагу 2.
   Повторяйте это для каждого сообщения пользователя, включая уточнения,
   вопросы, ревью и мелкие правки. Не опирайтесь только на описания навыков
   или память прошлых ходов. Для регулярной работы используйте локальные
   файлы; не скачивайте и не обновляйте upstream при каждом запросе.
2. Выберите применимые процессы из локальной коллекции `.claude/skills/` и
   прочитайте каждый выбранный `SKILL.md` перед работой, которой он управляет.
   Предпочитайте проектную копию одноимённому глобальному навыку.
3. Кратко сообщите на русском, какие навыки вы применяете и почему. Для
   простого вопроса достаточно навигационного навыка; не навязывайте
   реализационный процесс информационному запросу.
4. Следуйте выбранному флоу software-development-workflow и его чек-листам.
   Если в ходе хода задача меняется, пересмотрите выбор навыков.
5. Если нужный навык отсутствует или не читается, сообщите точный путь и
   ограничение. Не утверждайте, что навык применён, и не подменяйте его
   инструкциями по памяти.

## Контекст продукта

- Цель: внутренний сервис управления заказами оптовой торговли — каталог,
  корзина, оформление, статусы и история заказов.
- Архитектура: Go-модуль `orders`; HTTP API на Connect по контрактам `proto/`;
  PostgreSQL через `pgx` и `sqlc`, миграции `goose`. Слои и границы — в
  `docs/hld/README.md`.
- UI: Vite + React + TypeScript в `web/`, компоненты shadcn, Tailwind v4;
  токены в `web/src/styles.css`.
- Данные: справочники контрагентов и номенклатуры синхронизируются из учётной
  системы; словарь данных — `docs/data-dictionary.md`.
- Ограничения: секреты только через окружение; прямые записи в
  production-БД запрещены.

## Конвенции работы

- Отвечайте на русском, если пользователь не попросил другой язык.
- Перед правками смотрите фактические файлы и `git status`; сохраняйте
  существующие изменения пользователя, включая untracked-файлы. Для поиска
  используйте `rg`.
- Изменения делайте маленькими и управляемыми; существенные допущения
  формулируйте явно. Спрашивайте, только когда нехватка информации блокирует
  решение или требуется разрешение.
- Явные инструкции пользователя важнее правил флоу. Навыки не авторизуют
  коммиты, push, деплой и запись в production.
- Новые ветки: `codex/<краткое-описание>`, если пользователь не указал иное.
- Секреты (ключи провайдеров, пароли БД) не храните в файлах репозитория.
- Запускайте проверки, соответствующие изменению; сообщайте, что прошло,
  что проверить не удалось и какие остались ограничения. Не приписывайте
  непроведённые проверки.

## Команды проверки

- `go test ./...` — модульные и интеграционные тесты Go.
- `go build ./...` — сборка модуля.
- `buf lint` и `buf generate` — контракты; после генерации пересоберите
  зависимые пакеты.
- `sqlc generate` — регенерация слоя доступа к данным после правки SQL.
- `goose up` — миграции dev-БД (параметры подключения в `MANUAL.md`).
- `pnpm typecheck` и `pnpm build` в `web/` — типы и production-сборка UI.
- `pnpm test:e2e` в `web/` — Playwright smoke; детали в `web/e2e/README.md`.

## Graphify — навигация по кодовой базе

- Навык: `.claude/skills/graphify/SKILL.md`. Для архитектуры, связей символов
  и влияния изменений сначала спрашивайте граф:
  `graphify query "<вопрос с именами символов или путей>"`. Если доступны
  MCP-инструменты Graphify (`query_graph`, `get_node`, `get_neighbors`,
  `shortest_path`, `graph_stats`), используйте их.
- Запросы делайте узкими (обычно 2000 токенов); не читайте весь JSON графа.
  Рёбра INFERRED — навигационные подсказки: перед правками проверяйте
  исходники.
- Если графа нет, соберите его по инструкции навыка; после правок кода
  обновите граф, прежде чем полагаться на него или завершать задачу.
- Если граф устарел, запрос не нашёл нужного или Graphify недоступен,
  используйте точечный `rg` и чтение исходников; сообщите об ограничении.
- `graphify-out/` генерируется локально и игнорируется Git; не коммитьте его.

## Правила агентной работы
- Ведите AGENTS.md и CLAUDE.md полностью на русском языке: заголовки, пояснения, правила и новые разделы. Сохраняйте без перевода только команды, пути, имена файлов, названия продуктов и технические идентификаторы. При настройке существующего продукта переведите и остальные разделы этих файлов, сохраняя смысл и силу всех пользовательских правил.
- Обязательно соблюдайте флоу разработки из **software-development-workflow**. Перед изменением прочитайте `.agents/references/software-development-workflow/docs/workflow.md`, карту `.agents/references/software-development-workflow/docs/upstream.md` и `docs/workflow.md` продукта.
- Используйте проектные навыки из `.agents/skills/` (Codex) и `.claude/skills/` (Claude), роли из `agents/` и материалы из `references/` этих каталогов. Эти версии имеют приоритет над одноимёнными глобальными навыками. Применяйте навыки по характеру задачи; не отменяйте обязательные проверки процесса.
- Держите в этом файле, помимо блока платформы, разделы продукта: правила на каждый запрос (перед сообщением выбирать применимые навыки из установленных проектных и сообщать на русском, какие применяются и почему; при наличии using-agent-skills начинать с его чтения), таблица маршрутизации задач по навыкам, краткий контекст продукта, конвенции работы, команды проверки и раздел навигации Graphify.
- Порядок работы: контекст → уточнение требований → проектирование → планирование → реализация → проверка → независимое ревью → выпуск → развитие. Выполняйте применимые согласования и проверки software-development-workflow.
- Храните требования, HLD/LLD/ADR, контракты и доказательства проверок в Git продукта; обновляйте затронутую документацию вместе с кодом. Не выдумывайте результаты или согласования.
- Настройка и запуск описаны в `MANUAL.md`. Состав и происхождение проектного набора зафиксированы в `docs/agent-skills.md`.
- Для управления набором читайте `.agents/skills/go-project-platform-manager/SKILL.md`. Перед установкой или обновлением покажите структурированный список навыков, источников, версий, агентов и референсов для согласования. Глобальное обновление не обновляет проектные копии.
- Если проектные материалы отсутствуют, завершите согласованную установку; не подменяйте их молча глобальными версиями. В новом worktree материалы приходят из Git; восстанавливайте только генерируемые артефакты (например, граф graphify).
