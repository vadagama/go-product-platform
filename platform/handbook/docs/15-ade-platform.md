# ADE: gpp и управление навыками ИИ

## Глобальный bootstrap и готовность продукта

`python3 installer/gpp.py install-cli` из доверенного стартового набора устанавливает
CLI и регистрирует `go-platform-bootstrap` в обоих глобальных каталогах. После этого
скилл вызывается из любого Git-продукта; его runner `scripts/gpp.py` использует
собственный runtime, не требует PATH или исходного клона. Поддержку обнаружения
глобальных Agent Skills нужно проверить в выбранном агенте ADE.

Основной вход после глобальной установки — `/go-platform-bootstrap Подготовь этот проект
к разработке` в целевом продукте (в Codex — `$go-platform-bootstrap`/выбор скилла).
Агент проводит опрос в чате по одному вопросу: продукт и целевые платформы,
предложенный стек и локальное окружение, опциональные AI/canvas, разрешение
инвентаризации и итоговый план. Пользователь не заполняет JSON, не выбирает
имена профилей и не запускает CLI. После подтверждения агент сам выполняет настройку.
Slash-вызов поддерживается не каждой ADE; скилл не изменяет её парсер команд.

По ответам опросника агент готовит workflow, структуру, инструменты,
зависимости и запускаемый каркас по выбранному профилю, сохраняя существующий код.
`gpp init --setup --profile web --json` выдаёт шаблон контракта с обязательными
компонентами. Агент заполняет реальные пути и проверки, затем применяет согласованный
план через `gpp init --project . --setup-plan <plan.json> --approve`.
Контракт сохраняется в Git продукта как `go-product-platform.setup.json`.

`gpp doctor --ready` требует профиль и его глобальные навыки, проверяет артефакты
и исполняет свежие команды инструментов и каждого компонента. Это запуск доверенного
кода продукта, а не пассивная инспекция. Успешный `doctor --strict` подтверждает
только материалы платформы. `init --offline` по-прежнему ничего не устанавливает.

## ADE — начальная настройка v14: навыки глобально, документация внутри проекта {#ade-bootstrap-v14}

> **Исторический раздел v14.** В v15 первоначальная настройка работает через опросник и управляющий проектный навык; порядок ручной установки и пустой каталог проектных навыков ниже заменены разделом [ADE v15](#ade-skills-manager-v15). Остальная модель глобального хранения остается действительной.

**Нормативное решение:** все переиспользуемые навыки установлены **один раз** в домашней директории macOS-пользователя. При создании нового проекта агенты пользуются только этими общими навыками. `.go-product-platform/` сохраняется в каждом checkout/worktree для архитектурной документации, профилей, шаблонов, локального графа и контекста продукта, **но не является копией библиотеки общих навыков**.

### Какие каталоги являются глобальными {#ade-global-dirs}

| Глобальный путь на Mac | Назначение |
|---|---|
| `/Users/olegkrasnov/.agents/skills/` | Общие навыки для Codex, Zed и совместимых сред |
| `/Users/olegkrasnov/.claude/skills/` | Те же общие навыки для Claude Code |
| `~/.agents/go-product-platform/vendor/` | Единые неизменяемые снимки GitHub-репозиториев с полным набором references |
| `~/.agents/go-product-platform/global-skills.lock.json` | Зафиксированные Git commit SHA источников; глобальный источник истины |
| `~/.local/bin/gpp` | CLI для установки и обновления платформы в проектах |

`gpp` вычисляет пути через `$HOME`, поэтому не содержит жёстко заданного имени пользователя. На Mac с этим профилем `$HOME` равен `/Users/olegkrasnov`.

Источники включают [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills), выбранные навыки Go, Buf, shadcn, Vercel, Playwright, Swift/Android, семь [Навыки Orca](https://orca.dev/docs/cli/skills) и [Graphify](https://github.com/Graphify-Labs/graphify). Для Addy хранится полный набор совместимых общих `references`, поскольку выборочная установка отдельных навыков может не перенести ссылки на общие чек-листы.

### Установка на новую машину и запуск первого проекта {#ade-global-install}

```sh
# ОДИН РАЗ на Mac: установить CLI из доверенного starter kit
python3 installer/gpp.py install-cli

# Посмотреть состав и источники без изменения системы
gpp setup-global --skills --graphify --orca --dry-run

# ОДИН РАЗ на пользователя: навыки в ~/.agents и ~/.claude
gpp setup-global --skills --graphify --orca

# В КАЖДОМ новом Git-проекте: только локальный Handbook и настройки
cd /path/to/my-product
gpp init --project . --offline
gpp doctor --project . --strict
```

Установщик использует `platform/manifests/global-skills.json`: имя навыка, GitHub-репозиторий и расположение `SKILL.md`. Репозитории загружаются глобально, версия фиксируется в `global-skills.lock.json`; при столкновении имен **существующий навык не перезаписывается**. Orca и Graphify используют собственные механизмы глобальной установки. Скрипты из сторонних навыков не выполняются установщиком.

Внутри проектного репозитория остаются только малые **отслеживаемые** файлы `.gitignore`, `AGENTS.md`, `CLAUDE.md`, `orca.yaml` и `go-product-platform.lock.json`. Каталог `.go-product-platform/` автоматически добавляется в `.gitignore`.

### Что получает новый проект {#ade-project-layout-v14}

```text
my-product/
├── .gitignore                     # /.go-product-platform/
├── AGENTS.md                      # Короткие правила и ссылки на global skills
├── CLAUDE.md                      # Мост к AGENTS.md, глобальные Claude skills
├── orca.yaml                      # Только восстановление документации в worktree
├── go-product-platform.lock.json  # Версия платформы, не копия global lock
└── .go-product-platform/          # Игнорируется Git
    ├── handbook/                  # Архитектура, HTML и Markdown
    ├── constitution.md
    ├── references/
    ├── profiles/
    ├── manifests/global-skills.json
    ├── graphify/out/             # Свой индекс на каждый worktree
    ├── project-skills/           # Пусто по умолчанию
    └── tools/
```

В проекте **не появляются** `.agents/skills` и `.claude/skills` для общего каталога. Их наличие допустимо только для навыка, специально созданного под этот продукт, после явного решения и review. Наличие всех глобальных навыков на машине не означает, что агент должен читать их целиком перед каждой задачей.

### Жизненный цикл worktree в Orca {#ade-worktree-v14}

Корневой отслеживаемый `orca.yaml` содержит:

```yaml
scripts:
  setup: |
    gpp init --project . --offline
  archive: |
    gpp clean --project . --worktree
setupAgentStartupPolicy: wait-for-setup
```

Это быстрая локальная операция: **без скачивания навыков, клонирования GitHub, установки Node/Go, Docker, сборки приложения или полного Playwright**. В отдельном worktree создаются собственное руководство и каталог графа; общие навыки читаются из глобального каталога пользователя. Если `orca.yaml` уже содержит пользовательские hooks, установщик сохраняет файл и предлагает фрагмент для ручного слияния.

Graphify CLI устанавливается глобально, но **результат индексации должен быть отдельным у каждого worktree** (`.go-product-platform/graphify/out`). Команда `gpp graph-build` вызывается только при необходимости, а не после каждого изменения кода.

### Собственные навыки — только по контексту продукта {#ade-custom-skills}

Новому проекту не нужны автоматически сгенерированные `wails3-desktop`, `connectrpc-v2`, `go-domain-*` и другие собственные навыки только потому, что они предусмотрены в руководстве. Навык создается тогда, когда появляется **реально уникальное** проектное правило, нестандартная интеграция или повторяемый сценарий. Черновики допускается хранить в `.go-product-platform/project-skills/`. Если навык должен переиспользоваться членами команды, его **осознанно** публикуют как версионируемый артефакт проекта, а не автоматически превращают в глобальное правило для всех продуктов.

### Воспроизводимость и границы безопасности {#ade-global-security}

- **Два независимых lock-файла:** проектный `go-product-platform.lock.json` фиксирует версию платформы; пользовательский `~/.agents/go-product-platform/global-skills.lock.json` фиксирует SHAs общих навыков.
- **Управляемые обновления:** переустановка другого `main` из GitHub не должна молча менять инструкции во всех проектах; глобальное обновление — отдельная осознанная операция с тестом.
- **Изоляция:** глобальные навыки являются руководствами для агента, но сами по себе не получают учётные данные рабочей среды; графы и результаты проверок не общие между worktree.
- **Проверка:** `gpp doctor --strict` определяет отсутствие обязательных глобальных навыков, неправильную настройку `orca.yaml` и оставшиеся ссылки v13.

Источники: [Graphify installation](https://github.com/Graphify-Labs/graphify) · [Addy Osmani Навыки агентов](https://github.com/addyosmani/agent-skills) · [Навыки Orca Registry](https://orca.dev/docs/cli/skills).

## Миграция v13 → v14 без потери проектных навыков {#ade-migration-v14}

> Исторические инструкции для перехода с v13; текущая [миграция v14 → v15](#ade-v15-migration) описана отдельно.

**Изменение:** в v13 общие навыки лежали в игнорируемом проектном каталоге и были представлены ссылками `.agents/skills` и `.claude/skills`; в v14 эта библиотека находится глобально на Mac. Отныне создание очередного проекта и worktree не переустанавливает навыки.

```sh
# После установки gpp v14 (на машине разработчика)
gpp setup-global --skills --graphify --orca

# Один раз для каждого ранее созданного проекта v13
cd /path/to/existing-v13-project
gpp migrate --project .
gpp doctor --project . --strict
```

Миграция удаляет **только ссылки и файлы, созданные старым bootstrap v13**. Уже созданные разработчиком проектные навыки в проекте не затрагиваются. Версия платформы обновляется в корневом lock-файле; обновленные отслеживаемые точки входа нужно зафиксировать в Git. Нельзя молча обновлять чужую ветку с lock v13: её переход делается явной командой.

**Контрольный инвариант:** `gpp init` не должен менять файлы в `$HOME/.agents/skills` и `$HOME/.claude/skills` и не должен иметь сетевых вызовов. Этот инвариант проверяется девятью локальными тестами установщика, включая worktree, сохранность пользовательских инструкций, конфликты глобальных навыков и миграцию.

## ADE v15: интерактивная установка и управление навыками ИИ через агента {#ade-skills-manager-v15}

**Нормативное решение v15 (заменяет порядок ручной установки из исторических разделов [ADE — начальная настройка v14](#ade-bootstrap-v14) и [миграции v13→v14](#ade-migration-v14)):** пользователь описывает задачу Codex, Claude Code, Zed или Orca, а агент самостоятельно выполняет диагностику и настройку через установленный `gpp`. Установка и обновление навыков **всегда требуют явного подтверждения**. Есть также терминальный мастер вопросов `gpp wizard` для первого запуска без агента.

Наличие навыка в глобальном каталоге не означает его обязательное применение. Каждый продукт фиксирует список активных глобальных навыков в **отслеживаемом** `go-product-platform.lock.json`. Инструкции одного продукта не распространяются на другой. Проектные навыки хранятся в `.agents/skills/` и `.claude/skills/` под Git и не публикуются глобально автоматически.

| Где располагается | Содержимое | Версионирование |
|---|---|---|
| `~/.agents/skills/` | Общие навыки для Codex/Zed и совместимых сред | Глобальный SHA lock |
| `~/.claude/skills/` | Общие навыки для Claude | Тот же SHA lock |
| `~/.agents/go-product-platform/` | Git снимки, история обновлений, global-skills.lock.json | SHA каждого источника |
| `my-product/go-product-platform.lock.json` | Версия платформы, профиль, список активных имен | Отслеживается Git |
| `my-product/.go-product-platform/` | Руководство, конфигурация, активные навыки, локальный управляющий навык | Игнорируется Git |
| `my-product/AGENTS.md`, `CLAUDE.md` | Русские правила workflow и приоритета проектных навыков | Отслеживается Git |

### Сценарий первого запуска: мастер вопросов {#ade-v15-wizard}

**Опросник начинается с объяснения, что доступно**, а не с установки всего каталога. Последовательность:

1. Показать категории: Серверная часть на Go, PostgreSQL, Protobuf/Buf, Wails, React/shadcn, тесты, iOS/Android, AI SDK, Graphify и Orca.
2. Спросить разрешение прочитать только списки `SKILL.md` в двух глобальных каталогах. Если пользователь отказался, проверку пропустить.
3. Предложить профиль `go-api`, `web`, `desktop`, `mobile-native`, `ai` или `custom` и вывести имена и краткие описания входящих навыков.
4. Предложить включить дополнительные глобальные навыки в выбранный проект. После выбора и согласования установить проектные копии через `skills-project --approve`.
5. При согласии проверить отсутствующие навыки, показать источники GitHub; **отдельно запросить разрешение** на глобальную установку конкретных навыков.
6. Отдельно предложить **только проверку** обновлений на GitHub (сетевой запрос). При наличии версий показать текущий и предлагаемый commit SHA.
7. Вывести итоговый план и запросить финальное согласие. Отказ отменяет изменения и в проекте, и в глобальных каталогах.

Пример разговора с агентом:

> **Пользователь:** Настрой этот проект под Go API и React. Посмотри, какие навыки уже установлены, и предложи необходимые. Ничего пока не устанавливай.
>
> **Агент:** Можно использовать Тестирование Go, Go architecture, Buf/Protobuf, shadcn и Playwright. Разрешить проверить наличие в `~/.agents/skills` и `~/.claude/skills`?
>
> **Пользователь:** Да.
>
> **Агент:** Пять навыков есть, двух не хватает. Предлагаю активировать семь для проекта, а два отсутствующих установить глобально из указанных GitHub-репозиториев. Подтверждаешь?

Терминальный эквивалент — `gpp wizard --project .`, но **пользователь не обязан вводить его вручную**: агент использует машинный JSON-инвентарь и задаёт вопросы в чате. Терминальный мастер предназначен для пользователей, открывающих локальный starter kit без работающего агента.

### Проектный skill-manager: агент обслуживает платформу {#ade-v15-manager-skill}

В каждом проекте при `gpp init` появляется:

```text
my-product/
├── AGENTS.md
├── CLAUDE.md
├── orca.yaml
├── go-product-platform.lock.json
└── .go-product-platform/
    ├── active-global-skills.md
    ├── handbook/
    ├── project-skills/
    │   └── go-project-platform-manager/
    │       └── SKILL.md
    ├── graphify/out/
    └── tools/gpp.py
```

**Это единственный автоматически создаваемый проектный управляющий навык.** Он существует потому, что знает конкретный профиль и правила данного проекта. Общие навыки по Go, Wails, React, Protobuf, Graphify и Orca остаются глобальными. Управляющий навык вызывается через инструкции `AGENTS.md`/`CLAUDE.md`, а не за счёт дублирования в `.agents/skills` проекта.

Возможности для запросов на естественном языке:

| Запрос пользователя | Что делает агент | Граница безопасности |
|---|---|---|
| «Какие навыки у меня есть?» | С согласия читает глобальный инвентарь и активный список проекта | Не устанавливает ничего |
| «Включи Wails и UI-навыки» | Предлагает изменение профиля и записывает выбранные имена в project lock | Только после подтверждения |
| «Установи недостающие» | Выводит точные GitHub-источники, ставит выбранные навыки глобально | Отдельное согласие на установку |
| «Проверь обновления» | Получает upstream SHA для уже используемых источников | Только чтение, нет обновления |
| «Обнови эти навыки» | Проверяет источник, историю и согласованный exact-SHA план | Отдельное согласие; влияет на все проекты |
| «Проверим окружение» | Проверяет документацию, project bridge и наличие **активных** навыков | Без изменения глобальных каталогов |

### Контракт управления и CLI для агентов {#ade-v15-cli}

В отличие от большого скрипта с побочными эффектами, управление разбито на команды с разными разрешениями. Команды **исполняет агент**; они приведены в аккордионах как архитектурный интерфейс.

```sh
# Прочитать наличие глобальных skills после согласия пользователя.
gpp skills-inventory --project . --json

# Зафиксировать профиль продукта после согласия пользователя.
gpp skills-activate --project . --profile web --approve

# Установить именно указанные curated skills глобально после согласия.
gpp skills-install-global --names golang-testing,protobuf,shadcn --approve

# Для Graphify и Orca использовать официальные установщики (подтверждение отдельно).
gpp skills-install-external --names graphify,orca-cli --approve
```

Для проверки и актуализации навыков:

```sh
# Проверка свежести — только чтение GitHub, без установки.
gpp skills-check-updates --project . --selected-only --json \
  --output .go-product-platform/update-plan.json

# После анализа списка коммитов и ОТДЕЛЬНОГО согласия пользователя.
gpp skills-upgrade-global \
  --plan .go-product-platform/update-plan.json --approve

# Управляемые отдельно Orca/Graphify skills.
gpp skills-update-external --names orca-cli,graphify --approve
```

Файл плана содержит исходный SHA, предложенный SHA и репозиторий. Обновлятор проверяет, что HEAD **не изменился с момента согласования**, и не переписывает чужой глобальный skill-директорий. Старые снимки сохраняются. Если актуализация вызывает конфликт с пользовательским навыком, она останавливается без принудительной замены.

**Особенность обновления каталога:** проверка отслеживает уже закреплённые Git-источники. Новые имена навыков, которых ещё нет в манифесте Go Product Platform, включаются через отдельное версионированное обновление каталога платформы; они не устанавливаются автоматически только из-за того, что появились на GitHub.

### Глобальные изменения и совместимость между проектами {#ade-v15-global-updates}

Обновление навык влияет на **все** проекты на машине, потому что все они используют одну глобальную копию. Поэтому управляющий agent обязан показать:

- какие навыки и проекты потенциально затронуты;
- ссылки на источники и старый/новый commit SHA;
- меняется ли команда установки/запуск скриптов;
- план проверки после обновления и путь восстановления прежнего snapshot;
- какие навыки обслуживаются независимо (Orca/Graphify) и не покрываются обновлением снимков курируемых Git-репозиториев.

Чтобы проверка обновлений не влияла на кратчайший девелоперский цикл, ее запускают **только по просьбе пользователя** (либо после отдельно согласованной политики), а не в `orca.yaml` и не при каждом создании worktree. [Orca](https://orca.dev/docs/cli/skills) умеет управлять собственными глобальными навыками через встроенный updater; команду `orca skills update` следует запускать с явным согласованием. Для Graphify используется официальный `uv tool upgrade graphifyy`.

### Воспроизводимость и миграция с v14 {#ade-v15-migration}

Уже установленная v14 не обновляется скрыто: новый доверенный стартовый набор сначала заменяет CLI, затем агент предлагает **явную** миграцию проекта и согласование его активного профиля. Все `AGENTS.md`, существующие уникальные проектные навыки, индивидуальные hooks Orca и пользовательские глобальные навыки сохраняются.

```sh
# Этот набор выполняет агент после подтверждения пользователя.
python3 installer/gpp.py install-cli
gpp migrate --project .
gpp skills-inventory --project . --json
gpp doctor --project . --strict
```

В дальнейшем **каждый Orca worktree** выполняет исключительно `gpp init --project . --offline`; это восстанавливает локальную документацию, управляющий навык и описание активных навыков без сети, глобальных изменений, Docker build или тяжелых проверок.

### Критерии приёмки {#ade-v15-acceptance}

| Инвариант | Проверка |
|---|---|
| Пользователь отменил опросник | Никаких изменений в проекте или глобальных навыков |
| Пользователь отказал в чтении global каталогов | Нет проверки каталогов в опроснике |
| Навык активирован для проекта | Выбор записан в project lock; после согласования skills-project устанавливает проектные копии |
| Глобальный навык отсутствует | Отображается статус, установка только с отдельным подтверждением |
| User запросил «проверь обновления» | Только JSON-план и SHA, обновления не применяются |
| Upstream изменился после проверки | Отказ обновления, требуется новый план |
| Конфликт с чужим глобальным навык | Никакой принудительной перезаписи |
| Появился новый worktree | `gpp init --offline`, без сети и обновления навыков |
| Уже есть собственный проектный навык | Он сохраняется при повторной установке и миграции |

**Результат:** после первоначального доверенного подключения платформы пользователь управляет навыками в ADE обычными сообщениями, а не терминальными командами. Агент обязан объяснять последствия, получать подтверждение и проводить фактические операции с проверяемыми результатами.
